Casos de uso

Los 16 casos de uso del sistema, con actor, precondiciones, flujo principal, flujos alternativos y postcondiciones. Hacé clic en cada uno para abrirlo.

01 Registrar Paciente Recepcionista ▼

Precondiciones

  • El paciente debe presentarse en la clínica con su documento de identidad.
  • La recepcionista debe estar logueada en la aplicación.

Flujo principal

  1. Ingresa los datos del paciente (nombre, número de identidad, email y teléfono).
  2. Establece el tipo de notificación (llamada, WhatsApp, mail, mensaje).
  3. Valida con una foto contra el servicio del Renaper el documento.
  4. El sistema envía el mensaje de onboarding por WhatsApp o email según la preferencia del usuario.

Flujos alternativos

El usuario no tiene un teléfono celular ni email
  1. Se dejan los campos vacíos.
  2. El sistema no envía mensaje de onboarding.
  3. El usuario puede comunicarse con la clínica por teléfono y recibir llamadas a su número fijo como método de notificación.
El usuario no tiene ninguna clase de teléfono ni email
  1. Los campos se dejan vacíos.
  2. El sistema no intenta enviar ninguna notificación ni onboarding.
Falla la validación de Renaper
  1. Se realizan hasta tres intentos.
  2. Si no se puede validar la identidad del usuario se cancela el proceso de registro.
El sistema de Renaper está fuera de servicio
  1. Se continúa con el flujo normal.
  2. El usuario queda pendiente de validación hasta que realice el proceso desde su celular.
  3. Si pasada la semana no se valida correctamente, el usuario se marca como inválido hasta que realice la validación.
Email o teléfono ya está en uso
  1. No causa un error: la aplicación permite que un teléfono responda a más de un usuario, mientras sus logins sean válidos en el dispositivo.
  2. Informa al usuario para evitar cargas repetidas por error.
Documento de identificación en uso
  1. Se cancela el flujo de crear usuario, con la opción de enviar un código para recuperar contraseña.
El sistema está fuera de servicio
  1. Se guardan los datos del usuario en la base local y el identificador de proceso, para que se pueda terminar una vez regrese la conexión.
  2. El usuario puede presentarse y realizar las operaciones usando su número de identidad.

Postcondiciones

  • El usuario se crea en la base de datos.
  • Se envía el mensaje de onboarding.
  • El paciente queda registrado y habilitado para reservar turnos.
02 Autoregistro Paciente Paciente ▼

Precondiciones

  • El usuario debe tener un documento de identidad.

Flujo principal

  1. El usuario entra al flujo de registrarse.
  2. Completa sus datos personales (nombre, número de identidad, email y teléfono).
  3. Establece el tipo de notificación (llamada, WhatsApp, mail, mensaje).
  4. Valida con una foto contra el servicio del Renaper el documento.
  5. El usuario elige su contraseña.
  6. El sistema envía el mensaje de onboarding por WhatsApp o email según la preferencia del usuario.

Flujos alternativos

[Ver flujos alternativos — Registrar Paciente]

Comparte todos los flujos alternativos del caso de uso 01 (sin datos de contacto, falla o caída de Renaper, email/teléfono/documento en uso, sistema fuera de servicio).

Postcondiciones

  • El usuario se crea en la base de datos.
  • Se envía el mensaje de onboarding.
03 Iniciar Sesión Recepcionista Médico Paciente ▼

Precondiciones

  • El usuario debe tener un perfil existente.
  • El usuario tiene que haber creado su contraseña.

Flujo principal

  1. El actor ingresa su número de identificación y contraseña.
  2. Se valida que la contraseña corresponda al usuario.
  3. Accede al home de la aplicación con su tipo de perfil correspondiente.

Flujos alternativos

El usuario no tiene un perfil
  1. El botón de registrarse lo lleva al flujo [Autoregistrar Paciente].
  2. Médicos y recepcionistas deben ser creados por el panel de administración.
El usuario ingresa una contraseña incorrecta
  • Tendrá 4 intentos para volver a ingresar la contraseña.
El usuario falla 5 veces seguidas
  • Se bloquea la cuenta del usuario y se le envía un mensaje por su vía de notificación preferencial para que cree una nueva contraseña.

Postcondiciones

  • El usuario tiene una sesión iniciada y puede navegar la aplicación.
  • Se navega al home de la aplicación.
04 Reservar Turno Paciente Recepcionista ▼

Precondiciones

  • El usuario debe haber iniciado sesión (con perfil de Paciente o de Recepcionista).
  • Si el actor es Paciente, debe tener un usuario registrado.
  • Si el actor es Recepcionista, el paciente para el que reserva debe estar registrado.

Flujo principal

  1. Si el actor es Recepcionista, busca al paciente por número de identidad y lo selecciona. Si el actor es Paciente, el sistema usa al paciente con la sesión iniciada.
  2. El usuario elige la especialidad para el turno.
  3. El sistema muestra los turnos disponibles de los médicos que cubren la especialidad, empezando por los más cercanos y hasta 6 meses en el futuro.
  4. El usuario selecciona una franja.
  5. El sistema muestra los datos del turno (paciente, médico, especialidad, fecha y hora) para que el usuario los confirme.
  6. Si el usuario no los confirma, vuelve a seleccionar horario.
  7. Una vez confirmado, el sistema crea el turno asociado al paciente.

Flujos alternativos

El paciente no está registrado (solo Recepcionista)
  • La recepcionista busca al paciente por número de identidad y el sistema no lo encuentra.
  • El sistema ofrece iniciar el caso de uso Registrar Paciente.
  • Una vez registrado, la recepcionista continúa con la reserva desde la elección de especialidad.
El usuario filtra por médico
  • En la lista de turnos disponibles, el usuario selecciona un médico.
  • El sistema muestra solo los turnos disponibles de ese médico.
El usuario filtra por fecha
  • Indica una fecha de comienzo y una de fin (no puede superar el límite de 6 meses).
  • El sistema muestra los turnos disponibles en esa franja.
No existen franjas disponibles en los próximos 6 meses
  • El sistema informa que no hay turnos disponibles para la especialidad elegida.
Otro paciente confirma el turno antes
  • El usuario confirma una franja que ya fue reservada por otro paciente.
  • El sistema informa el error y solicita volver a seleccionar un turno.

Postcondiciones

  • El turno se crea en el sistema asociado al paciente, y es visible para todos los usuarios con acceso.
  • El paciente puede ver el turno en “Mis Turnos”, sin importar si lo reservó él o la recepcionista.
  • 48 horas antes del turno se envía una notificación al paciente, por su medio preferido, para que lo confirme.
05 Confirmar Turno Paciente ▼

Precondiciones

  • Haber sacado un turno.
  • Que falten menos de 48 horas para el turno.

Flujo principal

  1. El usuario recibe una notificación sobre un turno próximo.
  2. Desde la pantalla de confirmación puede notificar que se va a presentar al turno.
  3. Si el turno está confirmado, el paciente puede llegar tarde mientras sea durante el mismo horario del turno.

Flujos alternativos

El usuario no confirma el turno
  • Pasados los 30 minutos del turno se lo anotará como ausente y perderá la posibilidad de presentarse.
El turno no existe
  • Se muestra un mensaje de error y se elimina la notificación.
El turno fue cancelado
  • Se le informa durante la confirmación al usuario y se comienza el flujo de Reservar Sobreturno.

Postcondiciones

  • El turno se guarda como confirmado.
06 Reservar Sobreturno Paciente Recepcionista ▼

Precondiciones

  • Un turno se debe haber cancelado.

Flujo principal

  1. El usuario ve los horarios de sobreturno disponibles para el médico seleccionado.
  2. Una vez seleccionado el horario se mostrarán los datos para que los confirme el usuario.
  3. Si no lo confirma, vuelve a seleccionar horario.
  4. Una vez que confirme el turno, el mismo se crea en el sistema.

Flujos alternativos

El usuario filtra por fecha
  • Indica una fecha de comienzo y final para ver los turnos disponibles en esa franja (no puede superar el límite de 6 meses).
No existen franjas disponibles en los próximos 6 meses
  • Un mensaje de error informa al usuario que no hay turnos disponibles.
Otro paciente confirma el turno antes
  • Se muestra un error y se le pide al usuario volver a seleccionar un turno.

Postcondiciones

  • Se marca el turno cancelado como resuelto (reprogramado).
  • Se crea el sobreturno.
07 Consultar Mis Turnos Paciente ▼

Precondiciones

  • El usuario debe tener una cuenta registrada.
  • El usuario debe haber iniciado sesión en la aplicación.

Flujo principal

  1. El usuario ingresa a la sección “Mis Turnos”.
  2. El sistema identifica al usuario que inició sesión.
  3. El sistema consulta únicamente los turnos asociados a ese usuario.
  4. Muestra los turnos próximos ordenados por fecha y horario, indicando para cada uno el médico, la especialidad, la fecha, la hora y el estado (reservado, confirmado o cancelado).
  5. El usuario selecciona un turno para ver su detalle.
  6. El sistema muestra el detalle del turno y las acciones disponibles según su estado (confirmar, reprogramar o cancelar).

Flujos alternativos

El usuario consulta su historial
  1. El usuario selecciona la opción de ver turnos anteriores.
  2. El sistema consulta los turnos pasados del usuario.
  3. Muestra los turnos con su estado final (atendido, ausente o cancelado).
El usuario tiene un turno cancelado por el médico
  1. El sistema detecta que uno de los turnos del usuario fue cancelado por una cancelación de horario del médico.
  2. Marca el turno como cancelado y lo destaca en la lista.
  3. Ofrece al usuario la opción de reservar un sobreturno (caso Reservar Sobreturno).
No existen turnos registrados
  • El sistema informa que no existen turnos registrados para mostrar.
Error al consultar los turnos
  • El sistema informa que ocurrió un error y que no fue posible cargar la información.

Postcondiciones

  • Los turnos del usuario se muestran en pantalla.
  • Los turnos no sufren ninguna modificación.
  • El usuario puede acceder desde la lista a las acciones de confirmar, reprogramar o cancelar un turno.
08 Establecer Turno como Urgente Médico ▼

Precondiciones

  • El médico está registrado en el sistema.
  • El médico tiene la sesión iniciada.

Flujo principal

  1. El médico ingresa al sistema.
  2. Busca y selecciona el turno que desea marcar como urgente.
  3. El médico selecciona la opción “Establecer como urgente”.
  4. El sistema actualiza el estado del turno, asignándole la prioridad de urgente.
  5. El sistema confirma que el turno fue establecido como urgente.

Flujos alternativos

Flujo alternativo A — El turno no existe
  1. El médico busca un turno.
  2. El sistema no encuentra el turno solicitado.
  3. El sistema informa que no se encontró el turno.
Flujo alternativo B — El turno ya está marcado como urgente
  1. El médico selecciona un turno.
  2. El sistema verifica que el turno ya tiene prioridad urgente.
  3. El sistema informa que el turno ya está marcado como prioridad urgente.

Postcondiciones

  • El turno queda registrado con prioridad urgente.
  • El turno queda identificado y el sistema lo prioriza frente a otros turnos.
09 Actualizar Datos de Contacto Paciente Recepcionista ▼

Precondiciones

  • Tener una cuenta en el sistema.
  • Haber iniciado sesión en la aplicación.

Flujo principal

  1. El paciente accede a su perfil.
  2. El sistema muestra sus datos de contacto actuales: teléfono y correo electrónico.
  3. El paciente modifica el dato que quiere actualizar.
  4. El sistema valida el formato del dato ingresado.
  5. El paciente confirma el cambio.
  6. El sistema guarda los nuevos datos y los usa para los avisos y llamadas futuras.

Flujos alternativos

El formato del dato es inválido
  • Se muestra un mensaje de error y se solicita corregirlo.
El correo o teléfono ya pertenece a otra cuenta
  • El sistema informa que el dato ya está en uso y no guarda el cambio.
El paciente borra su correo teniendo el correo como canal de aviso elegido
  • El sistema le solicita elegir otro canal de notificación antes de guardar el cambio.
La recepcionista actualiza los datos en nombre del paciente
  • Cuando el paciente informa el cambio en el mostrador o por teléfono, la recepcionista accede a su ficha, modifica los datos y guarda el cambio.

Postcondiciones

  • Los datos de contacto del paciente quedan actualizados.
  • Los avisos posteriores se envían a los nuevos datos.
10 Cancelar Horarios Médicos Médico ▼

Precondiciones

  • El médico debe estar registrado en el sistema.
  • El médico debe haber iniciado sesión.
  • El médico debe tener horarios previamente establecidos.

Flujo principal

  1. El médico ingresa a la sección de administración de horarios.
  2. El sistema muestra los horarios disponibles del médico.
  3. El médico selecciona el horario que desea cancelar.
  4. El sistema muestra los datos del horario seleccionado para confirmar la operación.
  5. El médico confirma la cancelación.
  6. El sistema registra el horario como no disponible para la reserva de nuevos turnos.
  7. El sistema identifica si existen turnos asignados dentro del horario cancelado.
  8. Si existen turnos afectados, el sistema inicia el proceso de cancelación de esos turnos y la notificación a los pacientes correspondientes.

Flujos alternativos

El médico no tiene horarios establecidos
  • El sistema informa que no existen horarios disponibles para cancelar.
El médico no confirma la operación
  • El sistema cancela la acción y mantiene el horario sin modificaciones.
El horario seleccionado ya fue cancelado
  • El sistema informa que el horario ya no se encuentra disponible.
Existen turnos asignados al horario
  • El sistema cancela los turnos afectados y ejecuta el caso de uso Notificar Cancelación de Turno para informar a los pacientes.

Postcondiciones

  • El horario seleccionado queda registrado como no disponible.
  • No se pueden reservar nuevos turnos dentro del horario cancelado.
  • Los pacientes con turnos afectados quedan registrados para recibir la notificación.
11 Notificar Cancelación de Turno Sistema ▼

Precondiciones

  • Existe un turno previamente reservado.
  • El turno fue cancelado por un médico o por la clínica.
  • El paciente tiene registrado al menos un pedido de contacto.

Flujo principal

  1. El sistema detecta que el turno fue cancelado.
  2. Busca los datos del paciente asociado al turno.
  3. Consulta el medio de notificación preferido por el paciente.
  4. Prepara un mensaje informando la cancelación del turno, incluyendo los datos correspondientes (fecha, hora y médico).
  5. Envía la notificación mediante el medio de contacto seleccionado.
  6. Registra en el sistema que la notificación fue enviada correctamente.
  7. Actualiza el estado de la notificación para que pueda ser consultado por el perfil [Recepcionista].

Flujos alternativos

El paciente no tiene un medio de contacto registrado
  • El sistema registra que no fue posible enviar la notificación y deja pendiente el contacto telefónico.
El envío de la notificación falla
  • El sistema registra el fallo y marca al paciente como no notificado para que la recepcionista pueda contactarlo.
El medio de contacto no está disponible
  • El sistema intenta utilizar otro medio de contacto registrado si existe; de lo contrario, deja pendiente la notificación.
El turno ya había sido cancelado y notificado
  • El sistema evita enviar una notificación duplicada.

Postcondiciones

  • La notificación queda registrada con su estado correspondiente (enviada o pendiente).
  • La recepcionista puede consultar qué pacientes fueron notificados y cuáles necesitan ser contactados telefónicamente.
12 Configurar Horarios de Atención Médico ▼

Precondiciones

  • El médico debe tener una cuenta registrada en el sistema.
  • El médico debe haber iniciado sesión en la aplicación.

Flujo principal

  1. El médico ingresa a la sección de configuración de horarios.
  2. El sistema muestra las opciones para establecer los días y horarios de atención.
  3. El médico selecciona los días en los que desea atender.
  4. El médico establece los horarios de inicio y finalización de atención.
  5. El médico confirma la configuración.
  6. El sistema valida los horarios ingresados.
  7. El sistema registra los horarios de atención y habilita las franjas correspondientes para que los pacientes puedan reservar turnos.

Flujos alternativos

Horarios inválidos
  1. El médico establece un horario incorrecto (por ejemplo, una hora de finalización anterior a la hora de inicio).
  2. El médico confirma la configuración.
  3. El sistema detecta que los horarios son inválidos.
  4. El sistema informa el error y solicita corregir los horarios.
No se seleccionan días de atención
  1. El médico intenta confirmar la configuración sin seleccionar ningún día.
  2. El sistema informa que debe seleccionar al menos un día de atención.
  3. El sistema solicita completar la configuración.

Postcondiciones

  • Los horarios de atención quedan registrados en el sistema.
  • Las franjas horarias correspondientes quedan disponibles para la reserva de turnos por parte de los pacientes.
13 Ver Agenda de Turnos Médico Recepcionista ▼

Precondiciones

  • El usuario debe tener una cuenta registrada con perfil de Médico o Recepcionista.
  • El usuario debe haber iniciado sesión en la aplicación.

Flujo principal

  1. El usuario ingresa a la sección “Agenda”.
  2. El sistema identifica el perfil del usuario.
  3. Si el perfil es Médico, consulta únicamente los turnos asignados a ese médico. Si es Recepcionista, consulta los turnos de todos los médicos de la clínica.
  4. El sistema muestra la agenda del día actual, ordenada por horario, con el paciente, el médico, el estado del turno (reservado, confirmado, cancelado, ausente) y la marca de urgente si corresponde.
  5. El usuario puede cambiar de día o de semana para ver otras fechas.
  6. El usuario selecciona un turno para ver su detalle (paciente, especialidad, horario y datos de contacto).
  7. En el caso de la Recepcionista, el sistema también muestra las franjas libres de cada médico para poder ofrecerlas a quien llama o se presenta en el mostrador.

Flujos alternativos

El usuario filtra la agenda
  1. Selecciona un filtro por médico (solo Recepcionista), por especialidad, por fecha o por estado del turno.
  2. El sistema vuelve a consultar los turnos con los criterios elegidos.
  3. Muestra únicamente los turnos que cumplen con el filtro.
No existen turnos para la fecha seleccionada
  1. El sistema informa que no hay turnos registrados para esa fecha y, para la Recepcionista, muestra las franjas libres.
El médico no tiene horarios de atención en el día seleccionado
  1. El sistema informa que el médico no tiene horario de atención ese día.
  2. El sistema no muestra franjas libres para ese día.
Error al consultar la agenda
  1. El sistema intenta recuperar los turnos y falla.
  2. Informa que no fue posible cargar la agenda y permite reintentar.

Postcondiciones

  • La agenda correspondiente al perfil del usuario se muestra en pantalla.
  • Los turnos y las franjas no sufren ninguna modificación.
  • La Recepcionista puede identificar las franjas disponibles para reservar turnos por teléfono o en el mostrador.
14 Reprogramar Turno Paciente ▼

Precondiciones

  • El paciente debe tener una cuenta registrada.
  • El paciente debe haber iniciado sesión en la aplicación.
  • El paciente debe tener al menos un turno registrado para poder reprogramarlo.

Flujo principal

  1. El paciente ejecuta el caso de uso Consultar Mis Turnos y selecciona el turno que desea reprogramar.
  2. El sistema muestra los datos del turno seleccionado.
  3. El paciente selecciona la opción de reprogramar turno.
  4. El sistema muestra las franjas horarias disponibles para la especialidad y el médico correspondiente.
  5. El paciente selecciona una nueva fecha y horario.
  6. El sistema solicita confirmar los cambios.
  7. El paciente confirma la reprogramación.
  8. El sistema actualiza el turno con la nueva fecha y horario.

Flujos alternativos

No existen turnos registrados
  • El sistema informa que no existen turnos registrados, por lo que no hay nada para reprogramar.
No hay horarios disponibles
  1. El sistema busca las franjas horarias disponibles.
  2. Informa que no existen horarios disponibles para la fecha seleccionada.
  3. El paciente puede seleccionar otra fecha u operación.
El horario seleccionado deja de estar disponible
  1. Otro paciente reserva esa franja antes de confirmar la operación.
  2. El sistema informa que el horario ya no está disponible.
  3. El paciente debe seleccionar otra franja horaria.
El paciente cancela la reprogramación
  1. El sistema mantiene el turno original sin modificaciones.

Postcondiciones

  • El turno queda actualizado con la nueva fecha y horario.
  • El horario anterior queda liberado.
  • El nuevo horario queda reservado para el paciente.
  • Si el paciente cancela la operación, el turno original permanece sin modificaciones.
15 Cargar Sobreturnos Médico ▼

Precondiciones

  • El médico debe tener una cuenta registrada.
  • El médico debe haber iniciado sesión en la aplicación.
  • El médico debe tener horarios de atención configurados.

Flujo principal

  1. El médico ingresa a la sección de gestión de sobreturnos.
  2. El sistema muestra los días y horarios de atención del médico y las opciones para habilitar sobreturnos.
  3. El médico selecciona la fecha y la franja horaria en la que desea habilitar sobreturnos.
  4. El médico establece la cantidad de sobreturnos a habilitar.
  5. El médico confirma la carga.
  6. El sistema valida que la fecha y la franja correspondan a un horario de atención vigente, que no se superpongan con turnos existentes y que la cantidad sea válida.
  7. El sistema registra los sobreturnos y los deja disponibles para que los reserven los pacientes con turnos cancelados (caso Reservar Sobreturno).

Flujos alternativos

El horario no está disponible
  1. El médico selecciona una fecha y franja ocupada por turnos existentes, una fecha pasada o fuera de sus horarios de atención.
  2. El sistema informa el conflicto.
  3. Solicita seleccionar otra fecha o franja.
La cantidad de sobreturnos es inválida
  1. El médico ingresa una cantidad que no es válida (cero, negativa o que no entra en la franja seleccionada).
  2. El sistema informa el error y solicita corregir la cantidad.
El médico no tiene horarios configurados
  1. El sistema informa que debe configurar sus horarios de atención antes de cargar sobreturnos.
  2. El sistema no permite continuar con la carga.
El médico cancela la operación
  1. El sistema descarta los datos y no registra ningún sobreturno.

Postcondiciones

  • Los sobreturnos quedan registrados en el sistema.
  • Los sobreturnos quedan disponibles para que los reserven los pacientes con turnos cancelados.
  • Los turnos existentes no sufren modificaciones.
16 Seguimiento de Pacientes Afectados Recepcionista ▼

Precondiciones

  • El usuario debe haber iniciado sesión con perfil de Recepcionista.
  • Debe existir al menos un horario cancelado por un médico con pacientes afectados registrados (casos Cancelar Horarios Médicos y Notificar Cancelación de Turno).

Flujo principal

  1. El usuario ingresa a la sección “Cancelaciones”.
  2. El sistema muestra las cancelaciones de horarios recientes, con la cantidad de pacientes afectados y cuántos siguen sin resolver.
  3. El usuario selecciona una cancelación.
  4. El sistema muestra la lista de pacientes afectados, con los urgentes primero (marca de urgente del caso 8). Para cada uno indica el turno cancelado, el médico, el estado de la notificación (enviada o pendiente de llamar) y el estado de resolución (sin resolver, reprogramado, cancelado o resuelto por teléfono).
  5. El usuario selecciona un paciente pendiente (no notificado, o notificado sin resolver).
  6. El sistema muestra sus datos de contacto (teléfono, email y medio de notificación preferido).
  7. El usuario contacta al paciente por teléfono.
  8. El usuario registra el resultado del contacto (reprogramó, canceló o no respondió).
  9. El sistema actualiza el estado del paciente en la lista.

Flujos alternativos

El paciente no responde
  1. El usuario registra que no se pudo establecer contacto.
  2. El sistema deja al paciente como “pendiente de llamar” y guarda el intento con fecha y hora.
El paciente quiere reprogramar
  1. El usuario registra que el paciente desea un nuevo horario.
  2. Ejecuta el caso de uso Reservar Sobreturno en nombre del paciente.
  3. El sistema marca el turno cancelado como resuelto.
  4. Si no hay sobreturnos disponibles, el paciente queda como “pendiente de reprogramar” hasta que se carguen nuevos (caso Cargar Sobreturnos).
El paciente resuelve su turno desde la aplicación
  1. El paciente reserva un sobreturno desde la aplicación.
  2. El sistema actualiza automáticamente su estado a “reprogramado” y lo quita de los pendientes, sin intervención de la recepcionista.
No hay pacientes afectados o falla la consulta
  1. El sistema no encuentra pacientes afectados, o no puede recuperar la información.
  2. Informa la situación y, si fue un error, permite reintentar.

Postcondiciones

  • El estado de cada paciente afectado queda actualizado.
  • La recepcionista puede ver qué pacientes ya fueron resueltos y cuáles siguen pendientes, sin revisar llamadas ni conversaciones anteriores.
